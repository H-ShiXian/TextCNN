
# 数据库设计

本系统使用 **SQLite** 作为后端数据库，数据库文件存储于 `data/app.db`。系统具备自初始化能力，服务启动时将自动调用 `init_db()` 函数完成建表与初始化。数据库包含七张核心表，其逻辑关系紧密围绕“用户-题目-反馈-模型”的闭环流程设计。

## 1. 用户与会话管理

系统采用严密的认证机制：用户密码使用 **PBKDF2-SHA256** 哈希方案，经过 120,000 轮迭代并加盐处理后存储，确保密码原文不落库。登录令牌（Token）通过 `user_sessions` 表进行黑名单式管理，有效期为 30 天。

### 1.1 users 用户表

| 字段 | 类型 | 约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | TEXT | PRIMARY KEY | — | 用户唯一标识（如 demo_user） |
| `username` | TEXT | NOT NULL, UNIQUE | — | 登录用户名 |
| `password_hash` | TEXT | NULL | NULL | PBKDF2-SHA256 密码哈希值 |
| `role` | TEXT | NOT NULL | student | 角色：`student`（学生）/ `admin`（管理员） |
| `created_at` | DATETIME | NOT NULL | — | 账户创建时间 |
| `updated_at` | DATETIME | NOT NULL | — | 最后更新时间 |

### 1.2 user_sessions 会话表

| 字段 | 类型 | 约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `token` | TEXT | PRIMARY KEY | — | Bearer 认证令牌 |
| `user_id` | TEXT | NOT NULL, FK | — | 关联 `users.id` |
| `created_at` | DATETIME | NOT NULL | — | 会话创建时间 |
| `expired_at` | DATETIME | NULL | NULL | 过期时间（通常为创建后30天） |
| `is_revoked` | INTEGER | NOT NULL | 0 | 撤销标记：0=有效，1=已撤销 |

## 2. 题目数据核心

`questions` 表是业务逻辑的中枢，记录了从录入到掌握的全生命周期数据。系统支持手动录入、文件导入和 OCR 识别三种渠道。

### 2.1 questions 题目表

| 字段 | 类型 | 约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | TEXT | PRIMARY KEY | — | 题目唯一标识（q_xxx） |
| `user_id` | TEXT | NOT NULL, FK | — | 关联 `users.id` |
| `stem` | TEXT | NOT NULL | — | 题干文本内容 |
| `options_json` | TEXT | NULL | NULL | 选项列表的 JSON 字符串 |
| `correct_answer` | TEXT | NULL | NULL | 正确答案 |
| `analysis` | TEXT | NULL | NULL | AI 自动生成的解析文本 |
| `ai_label` | TEXT | NULL | NULL | 模型预测的初始学科标签 |
| `final_label` | TEXT | NOT NULL | — | 用户确认/修正后的最终标签 |
| `confidence` | REAL | NULL | NULL | 模型预测置信度（0.0~1.0） |
| `mastery_status` | TEXT | NOT NULL | unreviewed | 状态：`unreviewed`/`reviewed`/`mastered`/`careless` |
| `source_type` | TEXT | NOT NULL | manual | 来源：`manual` / `import` / `ocr` |
| `is_deleted` | INTEGER | NOT NULL | 0 | 软删除标记（0=活跃，1=已删除） |
| `created_at` | DATETIME | NOT NULL | — | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | — | 最后更新时间 |

## 3. 反馈与增量学习流水线

当用户纠正模型预测时，系统启动增量学习流程。反馈数据首先存入 `question_feedback`，随后由管理员触发任务刷入 `incremental_corpus`，最终追加至物理训练文件。

### 3.1 question_feedback 反馈表

| 字段 | 类型 | 约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | TEXT | PRIMARY KEY | — | 反馈唯一标识（fb_xxx） |
| `question_id` | TEXT | NOT NULL, FK | — | 关联 `questions.id` |
| `user_id` | TEXT | NOT NULL, FK | — | 关联 `users.id` |
| `question_text` | TEXT | NOT NULL | — | 题目文本快照（防止原题被修改） |
| `predicted_label` | TEXT | NOT NULL | — | 模型原始预测标签 |
| `corrected_label` | TEXT | NOT NULL | — | 用户纠正后的标签 |
| `is_corrected` | INTEGER | NOT NULL | — | 是否被纠正：0=一致，1=已纠正 |
| `created_at` | DATETIME | NOT NULL | — | 反馈提交时间 |

### 3.2 incremental_corpus 增量语料表

| 字段 | 类型 | 约束 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | TEXT | PRIMARY KEY | — | 语料唯一标识（corpus_xxx） |
| `question_text` | TEXT | NOT NULL | — | 待加入训练集的文本 |
| `label` | TEXT | NOT NULL | — | 对应的正确标签 |
| `source_feedback_id` | TEXT | NOT NULL, FK | — | 关联 `question_feedback.id` |
| `write_status` | TEXT | NOT NULL | pending | 状态：`pending` / `written` / `failed` |
| `write_error` | TEXT | NULL | NULL | 写入物理文件失败时的错误信息 |
| `written_at` | DATETIME | NULL | NULL | 成功写入 `train.txt` 的时间 |
| `created_at` | DATETIME | NOT NULL | — | 语料创建时间 |

## 5. 索引与性能优化

为了确保在数据量增长后仍能维持秒级响应，系统针对高频查询场景设计了如下索引：

* **错题列表检索**：`questions(user_id, created_at DESC)` —— 提升个人中心按时间排序的查询速度。
* **状态统计分析**：`questions(final_label)` 与 `questions(mastery_status)` —— 加速仪表盘各学科分布统计。
* **会话验证**：`user_sessions(token)` —— 确保鉴权中间件在每次 API 请求时能快速验证身份。
* **批量刷入任务**：`incremental_corpus(write_status)` —— 方便管理员快速筛选 `pending` 状态的语料。
* **安全过滤**：`questions(is_deleted)` 与 `user_sessions(is_revoked)` —— 快速排除无效数据。
