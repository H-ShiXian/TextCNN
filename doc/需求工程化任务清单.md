# 基于TextCNN的智能错题分类系统-工程化任务清单

## 1. 文档目的
将《系统需求规格说明书》转换为可直接用于 AI 辅助开发的工程任务，统一开发输入、输出与验收口径，降低返工风险。

## 2. 工程范围与优先级

### 2.1 版本目标
- V1（MVP）：跑通“录入-自动分类-人工修正-保存-查询-统计”闭环。
- V2：补齐批量导入、模型评估后台、模型版本切换。
- V3：补齐 OCR、组卷导出、相似题推荐（可选高级功能）。

### 2.2 优先级定义
- P0：必须上线，缺失将导致核心流程不可用。
- P1：应上线，缺失将显著影响效率或体验。
- P2：可后续上线，缺失不阻塞主流程。

## 3. 模块工程化任务分解

## 3.1 AI 引擎模块

### FR-3.1.1 文本预处理（P0）
- 输入：原始题目文本（字符串）。
- 输出：分词结果、规范化文本、词表索引序列（定长）。
- 规则：空白字符清洗、异常字符处理、未知词映射到 UNK。
- 异常：空文本、纯符号、乱码文本需返回可解释错误码。
- 验收标准：
  - 给定同一输入，多次处理结果一致。
  - 非法输入不会导致服务崩溃。
  - 预处理平均耗时可观测且纳入日志。

### FR-3.1.2 自动学科分类（P0）
- 输入：预处理后的索引序列或原始文本。
- 输出：分类标签、置信度（0-1）、模型版本号。
- 异常：模型未加载、推理超时、输入无效。
- 验收标准：
  - 返回结构固定，包含 label/probability/model_version。
  - 单条推理接口平均响应时间 <= 500ms（本地基线）。
  - 返回概率值范围合法。

### FR-3.1.3 反馈增量入库（P0）
- 输入：题目文本、AI 预测标签、用户修正标签、时间戳。
- 输出：增量训练样本写入结果。
- 异常：重复提交、标签非法、存储失败。
- 验收标准：
  - 用户修正后可持久化到增量语料库。
  - 具备去重策略或重复标记机制。
  - 写入失败时有重试或补偿记录。

## 3.2 错题录入与采集模块

### FR-3.2.1 单题手工录入（P0）
- 输入：题干、选项、正确答案、个人解析。
- 输出：错题记录 ID。
- 验收标准：
  - 必填字段校验明确。
  - 保存成功后可立即查询。
  - 与自动分类流程无缝衔接。

### FR-3.2.2 批量题目导入（P1）
- 输入：JSON/Excel/TXT 文件。
- 输出：导入统计（成功数/失败数/失败原因）。
- 异常：格式不匹配、字段缺失、编码异常。
- 验收标准：
  - 支持最小可用格式模板。
  - 单次导入提供详细错误报告。

### FR-3.2.3 OCR 识别录入（P2）
- 输入：图片文件。
- 输出：识别文本及置信信息。
- 异常：图片不清晰、OCR 服务不可用。
- 验收标准：
  - OCR 失败时可回退为手动录入。

### FR-3.2.4 自动分类挂载（P0）
- 输入：新录入题目。
- 输出：AI 预判标签，可人工确认/修改。
- 验收标准：
  - 保存前允许用户覆盖 AI 标签。
  - 覆盖动作触发 FR-3.1.3。

## 3.3 错题本管理模块

### FR-3.3.1 检索与过滤（P0）
- 输入：学科、时间范围、掌握状态、关键词。
- 输出：分页列表。
- 验收标准：
  - 支持联合查询与分页。
  - 响应时间满足日常可用体验。

### FR-3.3.2 状态管理（P0）
- 输入：错题 ID、掌握状态。
- 输出：更新结果。
- 验收标准：
  - 状态变更可追踪。
  - 支持删除并保留必要审计日志。

### FR-3.3.3 详情展示（P1）
- 输入：错题 ID。
- 输出：题目全文、答案、AI 标签、备注。
- 验收标准：
  - 字段完整，格式展示正确。

## 3.4 智能复习与评测模块

### FR-3.4.1 学情看板（P1）
- 输入：用户维度错题数据。
- 输出：学科分布图、趋势图。
- 验收标准：
  - 图表数据与数据库统计一致。

### FR-3.4.2 组卷与导出（P2）
- 输入：筛选条件或勾选题目。
- 输出：无答案 PDF/Word。
- 验收标准：
  - 导出内容完整且可打印。

### FR-3.4.3 相似题推荐（P2，可选）
- 输入：当前错题文本。
- 输出：相似题列表及相似度。
- 验收标准：
  - 推荐结果具备可解释相似度。

## 3.5 后台管理模块

### FR-3.5.1 数据集管理（P1）
- 输入：语料增删改查请求。
- 输出：处理结果与变更记录。
- 验收标准：
  - 支持数据清洗与版本化管理。

### FR-3.5.2 模型版本管理与评估（P1）
- 输入：训练触发参数、模型版本切换指令。
- 输出：训练日志、Accuracy/Loss、当前生效版本。
- 验收标准：
  - 支持一键训练与版本回滚。
  - 指标结果可视化展示。

## 4. 非功能需求工程化指标

### NFR-4.1 性能
- NFR-4.1.1 分类接口 P95 响应时间 <= 500ms。
- NFR-4.1.2 单节点支持 >= 50 QPS（压测口径需统一）。

### NFR-4.2 可靠性
- NFR-4.2.1 AI 服务异常时，前端允许手动分类并正常保存。
- NFR-4.2.2 对极短、纯符号、乱码文本有稳定降级策略。

### NFR-4.3 兼容性
- NFR-4.3.1 Web 兼容 Chrome/Edge 主流版本。
- NFR-4.3.2 页面适配主流移动端分辨率。

## 5. API 契约草案（供后续实现）

### API-01 文本分类
- 路径：POST /api/v1/ai/classify
- 请求体：
  - text: string
  - user_id: string (optional)
- 响应体：
  - code: int
  - message: string
  - data:
    - label: string
    - probability: float
    - model_version: string

### API-02 分类修正反馈
- 路径：POST /api/v1/ai/feedback
- 请求体：
  - question_text: string
  - predicted_label: string
  - corrected_label: string
  - user_id: string
- 响应体：
  - code: int
  - message: string

### API-03 错题保存
- 路径：POST /api/v1/questions
- 请求体：题干、选项、答案、解析、AI标签、用户确认标签
- 响应体：记录 ID

## 6. AI 辅助开发执行规范

### 6.1 任务卡模板
- 任务编号：如 TASK-FR-3.1.2-001
- 目标：一句话定义功能边界
- 输入输出：明确请求与返回
- 非目标：本任务不处理的范围
- 验收项：至少 3 条可验证标准
- 测试项：正常、边界、异常各至少 1 条

### 6.2 提示词最小模板
- 背景：当前模块与依赖文件
- 目标：只实现一个明确功能
- 限制：禁止修改的文件或接口
- 输出：代码 + 测试 + 变更说明

### 6.3 合并门禁
- 必须通过：单元测试、接口测试、关键异常测试。
- 必须满足：返回结构稳定、错误码明确、日志可追踪。
- 必须记录：需求编号与提交记录映射。
