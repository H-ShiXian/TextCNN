# TextCNN 分类服务接口文档

## 1. 概述

- 服务名称：TextCNN Classification API
- 版本：v1
- 基础地址（本地默认）：`http://127.0.0.1:8000`
- 版本化前缀：`/api/v1`
- 数据格式：`application/json`
- 字符编码：`UTF-8`

## 2. 统一返回结构

所有 JSON 接口均返回统一结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

字段说明：

- `code`：业务状态码
  - `0` 表示成功
  - 非 `0` 表示失败（常见如 `400`、`422`、`500`）
- `message`：提示信息
- `data`：业务数据（失败时通常为 `null`，参数校验失败时为错误详情数组）

## 3. 状态码约定

- `200`：请求成功（`code=0`）
- `400`：业务参数错误（如 text 为空）
- `422`：请求参数校验失败
- `500`：服务器内部错误

## 4. 接口列表

## 4.1 健康检查（v1）

- 方法：`GET`
- 路径：`/api/v1/health`

成功示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "status": "ok",
    "version": "v1"
  }
}
```

## 4.2 获取标签列表（v1）

- 方法：`GET`
- 路径：`/api/v1/labels`

成功示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "labels": [
      "computer_architecture",
      "computer_network",
      "data_structure",
      "operating_system"
    ]
  }
}
```

## 4.3 文本分类预测（v1）

- 方法：`POST`
- 路径：`/api/v1/predict`
- 请求头：`Content-Type: application/json`

请求体：

```json
{
  "text": "简述进程与线程的区别"
}
```

成功示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "label": "operating_system",
    "confidence": 0.9721
  }
}
```

失败示例（text 为空，400）：

```json
{
  "code": 400,
  "message": "text 不能为空",
  "data": null
}
```

失败示例（参数校验失败，422）：

```json
{
  "code": 422,
  "message": "请求参数校验失败",
  "data": [
    {
      "type": "string_too_short",
      "loc": ["body", "text"],
      "msg": "String should have at least 1 character",
      "input": "",
      "ctx": {"min_length": 1}
    }
  ]
}
```

## 5. 兼容接口（非 v1）

以下接口用于兼容早期调用方式，建议新接入统一使用 `/api/v1/*`：

- `GET /health`
- `GET /predict?text=...`
- `POST /predict`

兼容接口同样返回统一结构 `code/message/data`。

## 6. 调用示例

## 6.1 cURL

```bash
curl -X POST "http://127.0.0.1:8000/api/v1/predict" \
  -H "Content-Type: application/json" \
  -d '{"text":"链表反转"}'
```

## 6.2 PowerShell

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/predict" \
  -Method Post \
  -ContentType "application/json" \
  -Body '{"text":"链表反转"}'
```

## 7. 前端对接建议

- 成功判断统一使用：`response.code === 0`
- 提示文案优先使用：`response.message`
- 业务数据统一读取：`response.data`
- 建议保留兜底：当网络异常时提示“网络或服务异常”

## 8. 运行与调试

启动命令：

```bash
uvicorn app:app --host 0.0.0.0 --port 8000 --reload
```

在线调试页面：

- Swagger UI：`http://127.0.0.1:8000/docs`
- ReDoc：`http://127.0.0.1:8000/redoc`
- 内置联调页：`http://127.0.0.1:8000`
