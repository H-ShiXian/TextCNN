# 基于TextCNN的智能错题分类系统需求规格说明书

## 1. 引言

### 1.1 编写目的
本文档旨在明确“基于TextCNN的智能错题分类系统”的软件需求，定义系统的功能需求与非功能需求。本文档将作为后续系统架构设计、数据库设计、编码开发及系统测试的基础依据。

### 1.2 项目背景
在计算机考研（408：数据结构、计算机组成原理、操作系统、计算机网络）及其他学科的备考过程中，学生需要花费大量时间整理错题。传统的错题本整理效率低、分类主要依靠人工、难以进行系统性的回顾与偏科分析。本项目利用自然语言处理技术，通过构建 TextCNN（Text Convolutional Neural Network）深度学习模型，实现错题文本特征提取与智能分类，结合传统 Web/移动端技术，打造一个高效率、智能化的错题管理闭环式系统。

---

## 2. 总体描述

### 2.1 产品构架
本系统采取前后端分离与 AI 服务解耦的架构：
*   **前端（Web/小程序）**：负责用户交互、题目录入、图表渲染与数据展示。
*   **后端（业务系统）**：处理用户认证、业务逻辑、数据库 CRUD 操作，并作为中间件对接 AI 服务。
*   **AI 引擎端**：基于 Python 构建的独立模型服务（整合现有的 `predict.py`、`textcnn_model.py` 等），对外提供文本分类 API。

### 2.2 用户类与特征
*   **普通用户（学生/备考者）**：需要录入错题、使用错题分类、进行错题复习与自测的使用者。
*   **管理员（系统维护者）**：负责管理系统基础数据、维护学科分类语料库、监控模型性能，触发模型重新训练（Retrain）。

## 3. 功能需求 (Functional Requirements)

### 3.1 核心智能分类模块（AI引擎）
*   **3.1.1 文本预处理**：系统接收外部输入的题目文本，自动进行分词、去停用词处理，并将其映射为针对当前模型的词向量索引（对接 `vocab_built.py` 的产物）。
*   **3.1.2 自动学科分类**：系统将预处理后的文本送入 TextCNN 模型，输出题目所属的学科分类标签（如：计算机网络、数据结构）及其预测置信度（概率值）。
*   **3.1.3 模型持续演进（反馈循环）**：当系统检测到用户修改了 AI 预测的分类标签（即人工纠错了模型的误判），系统需将该题文本与正确标签自动转存至增量语料库（如 `data/train.txt` 格式），以便后续进行模型的增量训练或微调。

### 3.2 错题录入与采集模块
*   **3.2.1 单题手工录入**：提供富文本或 Markdown 编辑器，支持用户手工输入/粘贴题目题干、选项、正确答案及个人解析。
*   **3.2.2 批量题目导入**：支持用户或管理员上传 JSON、Excel 或 TXT 格式的文件，系统自动解析（集成 `parse_json.py`）并批量存入错题库。
*   **3.2.3 图片 OCR 识别录入**：支持用户拍照或上传带有错题的图片，系统调用 OCR（光学字符识别）技术自动提取图片中的题目文本，极大降低用户的输入成本。
*   **3.2.4 自动分类挂载**：录入或导入题目后，系统自动调用 3.1 节的分类接口，并在界面上向用户展示 AI 预判的分类标签，允许用户确认或修改。

### 3.3 错题本管理模块
*   **3.3.1 错题检索与过滤**：支持通过“学科大类”、“录入时间范围”、“掌握状态”、“关键词”对历史错题进行多维度联合查询。
*   **3.3.2 错题状态管理**：允许用户对一道错题的掌握程度打标签（如：未复习、已复习、完全掌握、粗心致错），并支持修改和删除。
*   **3.3.3 错题详情展示**：展示带有格式的题目全文、标准答案、AI 分类标签及用户个人备注。

### 3.4 智能复习与评测模块
*   **3.4.1 学情数据看板（Dashboard）**：利用图表（如饼图、柱状图）统计用户在“数据结构、计组、操作系统、计网”各科目的错题分布占比，直观显示用户的知识薄弱点。
*   **3.4.2 错题组卷与导出**：用户可以勾选指定分类或指定状态的错题，系统自动生成无答案的纯净版 PDF/Word 试卷供打印复习。
*   *(可选高级需求)* **3.4.3 相似题型推荐**：系统根据当前错题的词向量特征，在总题库中检索并推荐文本相似度高的其他题目，供用户举一反三。

### 3.5 后台管理与系统维护模块
*   **3.5.1 数据集管理**：管理员可对原始训练语料（如 `Subject_data` 下的 `xiaosi.json` 等）进行增删改查及清洗操作。
*   **3.5.2 模型版本管理与评估**：在后台界面展示模型评估指标（集成 `evaluate_test.py` 的功能），如 Accuracy（准确率）、Loss（损失），允许管理员一键触发 `train.py` 使用新语料训练新版本的模型，并在多个 `.pth` 模型文件间进行切换回滚。

## 4. 非功能需求 (Non-Functional Requirements)

### 4.1 性能需求
*   **响应时间**：单条文本预处理及 TextCNN 模型预测的接口响应时间应在 500ms 以内，保障用户录入时的流畅体验。
*   **并发量**：在日常情况下，分类 API 单节点支持至少 50 QPS 的并发访问请求。

### 4.2 可靠性与可用性
*   **异常处理**：若 AI 服务由于 GPU 显存溢出或断网等原因宕机，前端需友善提示，并允许用户跳过 AI 自动分类，转为完全手动选择分类保存。
*   **鲁棒性**：针对极短文本、纯符号文本、乱码文本等非标准输入，模型预处理模块及 API 应具备异常捕获能力，并返回合理的失败提示或“未知分类”。

### 4.3 兼容性与易用性
*   前端界面需响应式设计，至少兼容主流 PC 端浏览器（Chrome, Edge）及主流移动设备分辨率。交互层级应当扁平，核心的“录入-确认分类-保存”流程应尽可能在弹窗或同一页面内闭环完成。
